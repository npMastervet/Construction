# ระยะ 0 — ข้อกำหนดสำหรับเริ่มพัฒนา

สถานะ: กำหนดค่าเริ่มต้นทางธุรกิจและสัญญาข้อมูลแล้ว ตามที่ผู้ใช้มอบหมายให้เลือกตามความเหมาะสม

ชุดนี้เป็นข้อกำหนดที่ใช้พัฒนาต่อจาก BaseReactAuth เมื่อรายละเอียดต่างจากเอกสารประเมินก่อนหน้า ให้ใช้ชุดนี้สำหรับรุ่นแรก ไม่ได้หมายความว่าโมดูลธุรกิจถูกพัฒนาแล้ว

## การตัดสินใจที่ใช้จริง

| ประเด็น | ข้อกำหนดรุ่นแรก |
|---|---|
| ข้อมูล | หนึ่งกิจการในหน้าจอเริ่มต้น; ทุก record ธุรกิจผูก Organization และทดสอบด้วยสององค์กรเพื่อพิสูจน์ isolation |
| ผู้ใช้ | Google Login ตามอีเมลที่เจ้าขององค์กรเพิ่ม; บัญชี User แยกจากสมาชิกองค์กร |
| สิทธิ์ | ระดับองค์กร OWNER / ACCOUNTANT / MEMBER; ระดับโครงการ MANAGER / RECORDER / VIEWER |
| BOQ | ประมาณต้นทุน แยกจากมูลค่าสัญญา มี revision และ baseline ที่อนุมัติแล้ว |
| ค่าใช้จ่าย | หนึ่งเอกสารต่อหนึ่งโครงการ/ผู้ขาย/VAT mode/rate มีรายการย่อยแบ่งหมวด |
| การจ่าย | หลาย Payment ต่อเอกสาร บันทึกการ reverse ได้; ห้ามจ่ายเกินยอด |
| ตัวเลข | เงินบาท; decimal string ที่ API, Decimal ใน DB; ปัด half-up; VAT เก็บ rate ต่อเอกสาร |
| การแก้ไข | draft แก้ได้, posted ยกเลิกพร้อมเหตุผลแล้วสร้างฉบับแทน; เก็บ audit |
| ไฟล์ | private storage adapter; เลือกผู้ให้บริการเมื่อเริ่มงานอัปโหลด |
| Offline | แสดงสถานะออฟไลน์ แต่ยังไม่รับบันทึกเพื่อ sync ภายหลัง |
| ข้อมูลเดิม | ไม่สมมติว่าไม่มีข้อมูล; สำรวจ/backup ก่อนเริ่ม migration ข้อมูลจริง |

## ข้อจำกัดของหลักฐาน

ยังไม่มี BOQ/ใบเสร็จของกิจการจริงให้ตรวจ ชุดตัวอย่างจึงเป็นข้อมูลสมมติที่กำหนดเพื่อทดสอบกติกา ไม่ใช่การยืนยันกับเอกสารงานจริง การตรวจตัวอย่างจริงยังเป็นเกณฑ์ก่อน UAT แต่ไม่ขวางการเริ่มพัฒนาจากข้อกำหนดนี้

รายการเพิ่ม เช่น หลายโครงการในหนึ่งบิล, retention, มัดจำ, WHT, รับชำระจากลูกค้า, เอกสารขาย และบัญชีเต็มรูปแบบ ให้เปิดเป็น scope เพิ่ม ไม่แทรกเข้ารุ่นแรกโดยอัตโนมัติ

## ลำดับดำเนินงานถัดไป

1. สร้าง MySQL สำหรับ dev/test โดยใช้ข้อมูลเชื่อมต่อที่กำหนดสำหรับ Construction แล้วตรวจ migration ปัจจุบัน
2. เพิ่ม Organization / OrganizationMember / Project / ProjectMember / Supplier / AuditLog ด้วย migration ใหม่
3. ทำ authorization service และทดสอบการเข้าถึงข้ามขอบเขตก่อนสร้างหน้าจอ
4. ทำ API และหน้าจอองค์กร สมาชิก โครงการ และผู้ขายตาม contract
5. ผ่านเกณฑ์ของระยะข้อมูลและสิทธิ์ แล้วจึงเริ่ม BOQ

งาน Auth ที่ค้างจากช่วงตั้งฐานต้องติดตามแยก: Google Login จริง, state binding, HttpOnly refresh cookie, logout/revocation และ multi-tab refresh ต้องผ่านก่อนเปิดใช้งานภายนอก ไม่ถือว่าระยะปรับฐานใน blueprint เสร็จครบเพียงเพราะ build ผ่าน
